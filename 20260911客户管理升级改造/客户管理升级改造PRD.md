## 1. 迭代目标与范围

本期只实现以下四项：

1. 买车线索详情按同手机号聚合展示关联线索。
2. 买车线索、卖车线索按同手机号同步跟进状态和跟进记录。
3. 三类线索列表按四种跟进状态增加 Tab 展示。
4. 意向线索按「手机号 + 咨询车辆 VIN」去重，并累计点击次数及按状态重新流转。

现状截图与 Figma 页面仅用于识别已有页面结构、字段和操作，不作为本期新增需求。本期不新增未列出的页面、字段、按钮、状态、校验、接口、提示文案或统计口径。

## 4. 跟进状态 Tab 与操作

### 4.1 Tab 规则

- 三类线索均使用：待跟进、跟进中、完成跟进、跟进失败。
- 每个 Tab 仅展示对应状态的线索。
- 状态变化后，线索从原状态 Tab 移出并进入新状态对应的 Tab。
- 当前页面保持原 Tab，不自动切换至新状态 Tab。
- 同手机号关联线索发生同步时，按相同规则在当前 Tab 中移出或保留。
- 三类线索的「待跟进」Tab 按页面已有时间字段正序排列；「跟进中」「完成跟进」「跟进失败」Tab 按页面已有时间字段倒序排列。买车线索、卖车线索使用「录入时间」，意向线索使用「创建时间」。
- 【本次更新】（2026-09-16 修正）买车、卖车、意向线索处于「待跟进」时，因尚未开始跟进，「线索跟进人」数据为空，列表与详情均显示为空（不再显示「-」）。

### 4.2 状态—操作映射

| 跟进状态 | 更多操作菜单 |
| --- | --- |
| 待跟进 | 分配线索、认领线索、删除 |
| 跟进中 | 新增跟进、删除 |
| 完成跟进 | 删除 |
| 跟进失败 | 删除 |

此映射适用于买车线索、卖车线索、意向线索。角色实际可见操作取「角色权限允许的操作」与「当前状态允许的操作」的交集。

## 5. 买车/卖车线索详情聚合（2026-09-16 卖车同步）

### 5.1 关联键与展示范围

- 关联键：手机号。
- 同手机号即关联，不要求姓名相同。
- 买车/卖车线索列表仍按多条记录分别展示；详情打开其中任意一条后，展示当前线索及同手机号的其他同类型线索。
- 区块标题随类型显示「买车线索列表」/「卖车线索列表」；字段均为咨询车辆、创建时间、跟进状态；排序均为当前线索置顶、其余按创建时间倒序。
- 详情基本信息中，买车/卖车线索处于「待跟进」时「线索跟进人」同样显示为空。
- 意向线索详情不做聚合，不展示车辆列表。
- 详情现有基本信息不变。

### 5.2 关联列表

| 项目 | 规则 |
| --- | --- |
| 区域名称 | 买车线索列表 / 卖车线索列表（随类型显示） |
| 位置 | 基本信息下方 |
| 数据范围 | 当前线索及手机号相同的其他同类型线索 |
| 字段 | 咨询车辆、创建时间、跟进状态 |
| 当前线索标记 | 不增加单独标记；当前线索由上方基本信息表达 |
| 排序规则 | 当前线索置顶，其余同手机号线索按创建时间倒序排列 |

### 5.3 意向线索详情的用户名（2026-09-16 YAN 确认）

- 意向线索详情不设「姓名」字段，基本信息首项及顶部展示改为「用户名」（微信用户名）。
- 【本次更新】意向线索详情基本信息增加「点击次数」字段，位于「咨询车辆」后，与列表值一致（2026-09-16 YAN 确认）。
- 【本次更新，2026-09-29 YAN 已确认（闸门 A）】意向线索详情增加「咨询记录」列表模块；每条记录展示「咨询车辆」「咨询时间」，按咨询时间倒序排列。列表包含首次咨询记录，记录条数等于点击次数。

### 5.4 跟进记录展示（对齐线上环境）

- 「跟进中」「完成跟进」「跟进失败」线索：在「创建客户」基础上展示「新增跟进」记录，字段为时间、「新增跟进」绿色标签、操作人、跟进结果、跟进内容（2026-09-15 YAN 确认跟进失败同样式）。
- 详情内新增跟进提交成功后，新记录写入当前线索及同手机号全部同步线索的时间线。

## 6. 买车 / 卖车同手机号同步跟进

### 6.1 数据关联键

- 关联键：手机号。
- 不要求姓名相同。
- 适用范围：买车线索、卖车线索；意向线索不纳入本期同步跟进范围。
- 买车线索仅在买车线索类型内同步；卖车线索仅在卖车线索类型内同步，买车与卖车之间不跨类型同步。

### 6.2 同步规则

- 【本次更新】买车线索在「待跟进」Tab 改变其中一条线索的状态时，仅同步改变该 Tab 内同手机号线索的状态。
- 【本次更新】同手机号但已位于「跟进中」「完成跟进」或「跟进失败」Tab 的买车线索保持原状态，不随待跟进线索变化。
- 卖车线索与买车线索使用相同规则（2026-09-15 YAN 确认同步）：在「待跟进」Tab 改变其中一条线索的状态时，仅同步改变该 Tab 内同手机号线索的状态；同手机号但已位于其他状态 Tab 的卖车线索保持原状态。
- 新增跟进记录时，跟进记录同步至关联线索；相同手机号的关联线索展示相同跟进记录。
- 同步后的状态流转遵循第 4.1 节；页面保持当前 Tab，不自动切换。

### 6.3 认领线索确认弹窗

- 买车线索「待跟进」Tab 点击「更多操作 → 认领线索」后，先展示确认弹窗，点击「确定」后再按第 6.2 节同步改变状态。卖车线索「待跟进」Tab 的认领交互与文案同买车线索（2026-09-15 同步）。
- 当前手机号仅有 1 条待跟进线索时，文案为「确认认领这条意向线索嘛?」。
- 当前手机号有多条待跟进线索时，文案为「该手机号下有N条待跟进线索，确认认领意向线索吗?」，其中 N 为当前待跟进 Tab 内该手机号对应的线索数量。
- 点击关闭按钮或「取消」仅关闭弹窗，不改变任何线索状态。

### 6.4 新增跟进弹窗

- 买车线索「跟进中」Tab 点击「更多操作 → 新增跟进」后，展示新增跟进弹窗。卖车线索同位置、同交互（2026-09-15 同步）。
- 必填字段为「跟进结果」「沟通方式」「跟进内容」；跟进内容最多输入 60 字。
- 跟进结果选项：跟进中、完成跟进、跟进失败。
- 沟通方式选项：电话、短信、微信、到店。
- 点击「确定」后，当前线索及该手机号下全部处于跟进中状态的买车线索同步更新为所选结果。
- 同手机号但处于待跟进、完成跟进或跟进失败状态的其他线索保持原状态；页面保持在跟进中 Tab，不自动切换。
- 点击关闭按钮或「取消」不提交本次跟进。

### 6.5 分配线索弹窗（2026-09-15 补充，对齐线上环境截图）

- 买车线索「待跟进」Tab 点击「更多操作 → 分配线索」后，展示分配线索弹窗。卖车线索同交互（2026-09-15 同步）。
- 弹窗标题「分配线索」；必填字段「线索跟进人」，由上下两个单选下拉组成：上方「请选择角色」，下方「请选择员工」。
- 未选角色时「请选择员工」置灰不可选；选择角色后，员工下拉展示该角色下的员工候选（原型为模拟数据）。
- 点击「确定」：当前手机号下全部待跟进线索进入跟进中，线索跟进人更新为「角色-姓名」，创建客户记录的「分配跟进人」同步更新；页面保持待跟进 Tab。
- 点击关闭或「取消」：不改变任何线索状态。
- 【待确认】《现有功能梳理》记录线上「分配后详情增加跟进记录」，但未提供该记录的类型与字段截图，原型暂仅更新创建客户记录的分配跟进人，不新增记录类型。

## 7. 意向线索去重、点击累计与重新流转

### 7.1 数据关联键

- 识别键：手机号 + 咨询车辆 VIN（车架号，列表中以「车架号」列展示）。
- 仅用于意向线索页。
- 仅当手机号和 VIN 均相同，才视为同一用户重复咨询同一辆车；重复查看同一车架号的车辆才增加点击次数。
- 【本次更新】品牌型号相同但车架号不同的，视为两条独立意向线索，不合并、不累计点击次数。

### 7.2 数据处理规则【本次更新，2026-09-29 YAN 已确认（闸门 A）】

| 原线索状态 | 同手机号再次咨询相同 VIN 的处理 | 点击次数 | 创建时间 | 跟进记录 | 咨询记录 |
| --- | --- | --- | --- | --- | --- |
| 待跟进 | 不新增列表行，更新原线索 | `n + 1` | 保持首次咨询时间，不更新 | 不变 | 保留历史记录，并追加本次「咨询车辆」「咨询时间」 |
| 跟进中 | 不新增列表行，原线索保持跟进中 | 原线索累计为 `n + 1` | 不更新 | 不变 | 保留历史记录，并追加本次「咨询车辆」「咨询时间」 |
| 完成跟进 | 不新增列表行，原线索重新流转至待跟进 | `n + 1` | 更新为本次咨询时间 | 已有操作记录完整保留 | 保留历史记录，并追加本次「咨询车辆」「咨询时间」 |
| 跟进失败 | 不新增列表行，原线索重新流转至待跟进 | `n + 1` | 更新为本次咨询时间 | 已有操作记录完整保留 | 保留历史记录，并追加本次「咨询车辆」「咨询时间」 |

其中 `n` 为再次咨询前该识别键对应原线索的点击次数。首次咨询时点击次数为 1，并生成 1 条首次咨询记录。此后每次咨询均追加 1 条对应的车辆及时间记录，因此「咨询记录」条数始终等于点击次数；列表按咨询时间倒序排列。

- 【本次更新，2026-09-29 YAN 已确认】存量线索按现有点击次数保留对应数量的咨询记录行；无法追溯的咨询时间留空，不编造时间。

原型交互入口（2026-09-16 实现）：因原型无真实用户点击环境，点击意向线索列表中的「咨询车辆」名称即模拟该用户再次点击咨询车况（同手机号 + 同车架号），按上表规则流转。

### 7.3 意向线索认领

- 【本次更新，2026-09-29 YAN 已确认】在意向线索「待跟进」Tab 点击「更多操作 → 认领线索」后，仅当前这条意向线索进入「跟进中」。
- 本规则不触发同手机号其他意向线索的状态变化；不补充跟进人赋值或确认弹窗规则。

## 8. 边界与验收标准

- 买车详情聚合仅按手机号关联买车线索，不以姓名作为关联条件。

- 三类列表仅新增四种状态 Tab，不在 Tab 中增加数量。

- 现有筛选项、分页、详情基本信息及已有操作文案不因本期调整而扩展；【本次更新，2026-09-29 YAN 已确认（闸门 A）】增加「咨询记录」列表除外。
